# Evaluation evidence for 2.0.0rc2

Publication note: the development checks below describe the pre-publication state. See the root README for current prerelease downloads.

## Current rc2 verification — 2026-09-10

On Windows / Python 3.12.14, **40 unittest methods passed**. The suite includes
the existing 300 numeric subcases and 120 fixed synthetic benchmark cases, plus
8 authored writing examples checked only for lexical safety. The current
[benchmark record](../bench/report/v2.0.0rc2.json) agrees with all 120 expected
labels using the same dataset digest as rc1. These results do not measure naturalness.

New regressions cover the bounded directional edit ratio, masked read-only
whole-document context on repair, and retaining advisory warnings without
repeated calls. The ratio golden changed from 2/35 to 2/36 because equal spans
now share the denominator with insertion/deletion spans. The initial ratio
regression incorrectly expected global PASS despite an alignment warning; it
now asserts that specific WARN and the absence of a constraint failure.

The repository guard reported zero errors and zero warnings; `git diff --check`
found no whitespace errors. Name/description frontmatter, invocation metadata
and all six genre guides match the v1.1.0 work copy. The official Skill validator
returned `Skill is valid!` with a restricted parser shim after byte/text comparison
of the unchanged metadata; PyYAML-backed validation remains unrun.

[Eight authored examples](../examples/natural-writing.json) record requests,
source text, candidates and same-author review notes. They exercise edit,
rewrite, draft and audit choices across six genres. Their creation and inspection
are illustrative editorial work, not independent forward-testing, recorded Astra
API calls, a blind evaluation or evidence of a measured preference improvement.
No live model integration or human naturalness comparison was run.

Full and Lite archives are generated in a new output directory to preserve rc1.
The packaging command validates every entry and byte, then runs the CLI, replay
and full test suite from an extracted archive. Its actual results are saved in
`package-verification.json` alongside the ZIPs; no hosted CI result is implied.

## Failures found and corrected locally

- Decimal normalization rounded integers beyond the active decimal precision.
  Exact tuple canonicalization now preserves all digits, with a regression test.
- Japanese integers and scientific-format Arabic integers had different keys.
  Both now pass through the same exact normalization.
- The initial character-count test overcounted its literal by one; the expected
  value was corrected after enumerating its Unicode code points.
- File reads normalized CRLF, affecting exact counts and unchanged replay bytes.
  Reads now preserve line endings and have an end-to-end regression case.
- An empty replacement with no numeric facts was not a hard violation. It now
  fails deterministically, including an injection-style deletion test.

## Explicitly not run

- A live Base LLM vs pipeline benchmark and provider-specific integration.
- An independent holdout and human naturalness/voice evaluation for v2.
- Hosted GitHub Actions for this unpushed candidate.
- Historical v1.1.0 behavioral evaluations: retained as inherited evidence only;
  the previously lost encrypted holdout was not recovered or replaced.

The replay fixtures are hand-authored, not recorded calls. The software's
prompt-injection tests validate data separation and output/gate mechanics; they
cannot establish resistance to every semantic attack against a model.

## Known limits to retain in future reports

Unregistered names, arbitrary claims, negation, certainty and causal attribution
can change without a hard failure. Numeric values can be reassigned within a
sentence while their inventory is unchanged. Unknown Japanese units and bare
Kanji numerals need explicit glossary protection. Unicode normalization may
equate typographic numeric precision; significant-figure preservation is not a
separate check. Markdown, quotations and prose containing punctuation are handled
heuristically rather than with a complete syntax tree. Bad sentence alignment
can produce false positives. A `WARN` is a request to inspect, not to rewrite.
