# Japanese Writing v2.0.0rc2 改善結果

Publication note: the development checks below describe the pre-publication state. See the root README for current prerelease downloads.

既存のJapanese Writingを引き継ぎ、Astraで自然な日本語を作成・推敲する手順へ改善した。
バージョンは正式公開前の `2.0.0rc2` とした。

## 今回改善した点

- 文のつながり、読み返す負担、説明の順序、書き手の語彙や調子を文脈から判断する手順を追加した。
- 共通規則の重複を整理し、短文はその場で仕上げ、長文は必要に応じて構成を確認する運用にした。
- 必須のアウトライン、自己採点、毎回の複数案、不要な見出し・総括を執筆の前提にしない。
- 修正案を原文・資料と照合し、意味の保存と読みやすさを別々に確認する。既に自然な箇所は残す。
- 任意の検証ループへ全文のマスク済み原文を参照情報として渡し、適切な表現への警告は再試行せず残せるようにした。
- 変更率が100%を超える不具合を修正した。変更率は自然さの点数として扱わない。

[修正前後の例](natural-writing-examples.ja.md)と[利用手順](../references/astra-writing.md)で具体的な方針を確認できる。

## 引き継いだ検証機能

- 数値・単位・日付・時刻・URL・明示された数式・コード・辞書語の抽出と、変更・消失・追加の判定。
- 文対応、文字・文の変更率、10種類の警告ルール、文字数と指定語句・禁止表現の制約。
- 保護値のマスキングと復元、JSON Schemaによる出力検査、PASS/WARN/FAILの表層検査判定。
- findingのある文を対象とする最大2回の再修正。最終FAILでは候補稿を返さない。
- モデル関数の差し替え口、replay、CLI、YAML/JSON用語辞書、再現テスト、CI定義。

Skill名、自動呼び出しの設定、4つのmode、6つのgenre referenceは維持した。
通常利用中のローカルSkill、既存の作業コピー、公開リポジトリへの反映は行っていない。

## 確認結果

Python 3.12.14 / Windowsで40テストが通過した。これには数値変更・全角半角の300サブケース、6ジャンル計120件の固定合成ベンチマーク、作成例8件の表層情報保持チェックを含む。
公開用チェックはエラー0件・警告0件であった。Skill名・説明、自動呼び出し設定、6つのgenre referenceが従来版と一致することも確認した。
Skill validatorは、PyYAML不足のため変更していない2項目のfrontmatter専用shimを用いて実行した。通常のPyYAML環境で実行した結果とは区別する。

合成ベンチマークは20種類のシナリオを6ジャンルへ展開した開発用データである。
120件すべてが期待判定と一致したが、実LLMの誤り率や未知の文章への精度を表すものではない。

Full/LiteのZIPは `tools/package_v2.py` で生成する。生成時に内容・SHA-256・展開先のCLIとテストを検証し、結果をZIPと同じ場所の `package-verification.json` へ保存する。

## 検証範囲外・未実施

意味全体の保存、否定・確信度・因果、未登録の固有名詞や主張の追加は保証しない。
独立したAstra実行との比較、独立holdout、人による自然さの評価、GitHub上のCI実行と正式版公開は未実施である。作成例は方針の説明用であり、自然さの改善率を示す実験ではない。
既存リポジトリのライセンス未設定状態も維持した。
