# 本人の文体と改稿の確認

## 本人の材料を優先する

本人の原稿・メモ・過去文を区別する。今回の事実と、文体だけの参考文を分ける。
同じ用途の本人執筆文を優先し、著者・AI編集歴が不明な文は参考資料にとどめる。
短いチャットだけから申請書やレポートの文体を決めない。サンプルがなくても作業を進める。

「自分らしく」「構成から」の依頼では、語句を置換する前に、本人の中心的な判断、理由、残したい表現を原稿から拾う。
本人メモから組み直す場合は、元の完成稿の段落をひな型にせず、設問に答える論点から構成する。
編集では、既に適切な箇所は残す。説明の必要量が違う段落を均等に整えず、原稿にない教訓や展望を足さない。
文長や語尾の割合、変更率を目標にしない。

## 文体プロファイル

既存の指定プロファイルがあれば読む。保存・更新が求められた場合だけ、次の形で記録する。
原稿や個人情報を公開リポジトリに入れない。利用者の作業フォルダの私用ファイルを使う。

| 項目 | 記録するもの |
| --- | --- |
| 適用範囲 | 奨学金申請、講義感想、実験レポートなど |
| 根拠 | 本人確認されたサンプル名、該当箇所、AI編集歴の既知・不明 |
| 観察 | 語彙、説明順、接続、断定、敬体・常体の傾向を3〜5点 |
| 本人の指定 | 本人が好む・使わないと言った具体的な表現と用途 |
| 確度 | 確認済みの指定と、少量サンプルからの暫定推定を分ける |

別用途に傾向を無条件で移さず、本人の明示指定と提出条件を優先する。
サンプルの特徴的な一文や経験を新原稿へ流用しない。

## 改稿後の確認

まず原文・資料と全文を読み比べ、追加・脱落、主体、対象、時制、否定、条件、比較、確信度、文の働きを確認する。
「今後も努力を続けたい」→「学修に生かしたい」は、近い意味でも用途の意図を足すため、自動的に同義と扱わない。
「検証できた」→「検証した」も、達成の評価が必要なら維持する。

Full版でPythonが使える場合は、既存の `scripts/jw.py compare` に加えて次を実行できる。
いずれもスキル配置先を基準に絶対パスへ解決する。新規作成では完成稿と実際に与えられた材料を照合し、架空の原文を作らない。

```text
python scripts/voice_check.py review original.txt final.txt --max-chars 400
```

`REVIEW` は見直し候補あり、`CHECKED` は設定した表層検査で候補なしを示す。
否定・確信度・意図の表現数と、漢字・カタカナ・英字の語に続く一部助詞を比較するだけであり、意味保持は保証しない。
ひらがなの主体、同じ語の回数を保った意味変更、助詞の掛かる先などを見逃す。
引用符の中の表現も候補になり得る。コード・数式の一部は除外するが、完全な構文解析ではない。
候補を減らす目的で正しい文を変更しない。`review` の終了コード0は実行成功で、内容の合格を意味しない。
全文差分が必要なときだけ `--include-diff` を指定する。通常の結果に原稿本文は含めない。

## 検出器の結果を扱う場合

実測がなければ「未計測」とする。検出確率や、変更すれば下がる割合を推測しない。
語句・構造の特徴を、検出器の内部特徴と同一視しない。非検出の保証はしない。
実測の依頼では、ユーザー提供の結果、または実際に利用できる連携を使う。未依頼の外部投稿はしない。
同じ検出器・設定・投入範囲で比較し、AI-generated等の表示名と値をそのまま扱う。
最大3案を比較するなら、最初に全案の内容を監査する。判定結果を受けた追加編集は既定で2回とし、徹底した改善を依頼され実測の改善が続く場合は最大6回まで進められる。毎回全文を再確認し、改善停止や文章の悪化で終了する。
低い表示値だけで採用せず、意味保持・読みやすさ・本人の表現・設問適合を確認する。
本文を変更したら以前の測定結果を新稿へ引き継がない。

Full版では、ユーザーが実際に受け取った表示結果を私用のJSONに記録できる。
入力JSONは `detector`（文字列）、`measured_at`（タイムゾーン付きISO日時）、`scope`（`full_text`）、`settings`（辞書）、`metrics`（`label`と`value`の表示文字列の配列）を持ち、版が表示された場合だけ `version` を加える。
設定不明なら `settings` に不明である旨を記し、同条件と確認できたことにしない。

```text
python scripts/voice_check.py record final.txt --result displayed-result.json --output private-record.json
python scripts/voice_check.py verify final.txt --record private-record.json
```

この処理は検出器を呼ばない。結果は常に `user_reported` とし、測定の真正性や実際の投入内容は検証しない。
SHA-256で記録時のUTF-8ファイルと一致するかだけを確認する。`STALE`（終了コード3）なら過去の結果を採用しない。
測定時点の全文を私用で保持し、投稿した本文と一致するかも確認する。本文、結果、プロファイルは公開しない。
Lite版やPythonが使えない環境では手動で読み比べ、コードを実行したとは報告しない。
