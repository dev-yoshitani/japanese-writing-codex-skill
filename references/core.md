# Core rules

全genreに適用する。自然さは、意味を追えること、用途に合うこと、書き手の声が残ることで判断する。単語の禁止リストや均一な文章の型では判断しない。

## 情報を保護する

ユーザーが明示的に変更を許可しない限り、次を保持する。

- 数値、単位、日付、時刻、文字数条件
- 固有名詞、組織名、製品名、規格名
- 引用、出典、URL、注番号
- 数式、変数、添字、記号
- 専門用語、定義、条件、仮定、判断結果
- 主体と対象、不確実性、否定、限定、因果、比較の向き

引用、コード、表の値、数式は文体修正の対象外とし、必要なら周囲の説明を直す。

架空の事実、数値、引用、出典、経験、役割、成果、感情、根拠を追加しない。具体化に必要な情報が資料になければ作らない。確定が必要な情報は `要本人確認` または `要確認` とする。事実、解釈、希望、予定を混同しない。

## 書き手の声と用途に合わせる

語彙、丁寧さ、テンポ、断定の強さ、専門性、個性的な表現を生かす。本人の文章例があれば、提出要件と正確性に反しない範囲で参考にする。理解を妨げる癖だけを整え、全文を一段高い学術文体や一般的な模範解答へ均さない。

`edit`では、その変更が読みやすさや正確さに何をもたらすか判断する。改善する理由がある箇所を局所的に直し、目的を既に満たす箇所は残す。変更率の小ささだけを競わず、必要な推敲は行う。

## 意味に沿って文と段落を組む

- 一文の中心を明確にし、独立した判断を詰め込みすぎない。条件・因果・比較を一緒に読む必要があれば、そのまとまりを保つ。
- 前の文を受けて次の文が読めるように情報を置く。論理関係が明らかなら接続詞を足さず、必要な関係を示す接続詞は残す。
- 結論、理由、条件、補足の重みに応じて説明量を配分する。短い判断文が役立つ場面では使うが、文の長短、語尾、文頭、段落の長さを機械的に交互に変えない。
- 対象固有の事実や資料の具体情報を中心にする。背景の一般論が本文を覆うなら短くする。資料が支える限定的な結論は、その範囲のまま述べる。
- 段落や章に必要な役割を持たせる。全段落を同じ「主張→説明→まとめ」へ揃えず、事実や結果を示したところで終えてよい。
- 導入の細かい予告、各節末の再要約、結論での項目再列挙は、読者に役立つ場合だけ置く。既出内容の言い換えだけで文章を延ばさない。
- 資料にない社会的意義、教訓、将来展望や評価を補わない。各章へ例・意義・まとめを一律に付け足さない。

意味と読み手の負担を整えた結果として、長短や密度に違いが生じる状態を目指す。文章をわざと粗くしたり、論理を弱めたりする必要はない。

## 表現は機能で選ぶ

「重要なのは」「単なるAではなくB」「〜することが可能である」「以上のことから」などは、それだけで誤りではない。内容がない、論理関係が違う、同型が不要に続く、語数だけが増える場合に直す。真正な対比、必要な限定、規定の定型表現は残す。

主体が判断に必要なら明示し、自然に分かる主語や目的語は省略してよい。冗長な名詞化は意味を保って簡潔にする。実験方法、客観的手順、行為者が不明・不要な説明の受動態まで、一律に能動態へ変えない。

同じ対象の呼び名を理由なく変えない。意味を保つ反復、真正な三項列挙、指定された見出し・箇条書きは残す。装飾目的の言い換え、架空の対比、抽象的な強調、出所不明の権威づけは足さない。

意図的な誤字、文法崩し、不自然な口語化、架空の体験や感情、不可視文字・同形異字を使った検出回避は行わない。AI生成かどうかは断定せず、観察できる文章上の問題だけを扱う。

## 出力前の確認

1. 保護情報と意味を原文・資料と照合したか。数値が同じでも、誰の値か、どの条件の値かまで変わっていないか。
2. 追加した主張に根拠があり、否定、条件、確信度、判定を変えていないか。
3. mode、genre、提出条件に合い、元のよい表現や書き手の語彙を残したか。
4. 文同士のつながりを追え、必要な説明が残り、繰り返すだけの前置きや総括を足していないか。
5. 文や段落を同じ型へ揃えたり、変化を作るためだけに崩したりしていないか。
6. 架空の具体情報や、資料を越える意義・将来展望で文章を整えていないか。
7. 依頼を守ったこと自体を本文へ書いていないか。監査理由、必要な確認表示、指定の本文外count表示は除く。
8. 字数・語数条件があれば実際に数え、本文とは別に数値と数え方を示したか。

自然さを判断する具体的な手順は [astra-writing.md](astra-writing.md) に従う。機械検査の警告数や自己採点を、この確認の代わりにしない。
