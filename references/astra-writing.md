# Astraで自然な文章を書く

このSkillではAstraが文脈を読み、表現と構成を判断する。コードは数値などの確認を補助する。モデルの選択は利用側で行い、このreferenceから設定やAPIを変更しない。

## まず文章をつかむ

依頼と資料から「誰に、何を、どこまで伝えるか」を把握する。既存文章では、よい箇所の語彙、丁寧さ、言い切り方、説明の細かさを基準にする。別に渡された本人の文章例は文体の参考にし、その文章の経験や事実を今回の本文へ移さない。

短文ならこの把握と推敲を一度に行う。長文では、各段落が担う内容と、読者が理解する順序を内部で確認してから書く。すべての段落を同じ型へ整えるためのアウトラインは作らない。ユーザーに企画書や確認票を返すことを執筆の代わりにしない。

## 本文を仕上げる

- **文のつながり**：次の文が前の文の何を受けるかを確かめる。突然現れる主語、説明前の用語、曖昧な「これ」は、参照先が読める位置へ戻す。資料にない因果関係を接続詞で作らない。
- **読み返す負担**：主語と述語が離れすぎた文、何に掛かるか迷う修飾、入れ子の補足を整理する。条件と結論、比較する対象は一緒に理解できる位置に置く。長さだけを理由に分割しない。
- **語の働き**：誰が何をしたか、何がどうなったかを素直に述べる。意味を足さない名詞化や前置きは短くする。必要な専門語、定義、留保、自然な省略は残す。
- **段落の運び**：読者がいま必要とする情報を先に置く。結論を先に示す方が伝わる説明ではそうするが、体験の時系列や、留保を先に読む必要がある説明まで一律に結論先行にしない。
- **情報の重み**：重要な判断には必要な説明を添え、背景や補足には適切な長さを割く。元の具体的な情報を生かし、毎段落に「重要である」「今後に生かしたい」などの評価を付け足さない。

`edit`は不自然な箇所と、それに接する文のつながりを直す。自然さを改善できるなら局所的な語順変更や文の分割・結合はよい。問題のない段落まで書き換えない。構成全体の変更が必要でも、明示されたmodeを越えず、必要なら短く提案する。

`rewrite`は、資料の意味を保持して情報の順序から組み直す。`draft`は資料にある事実と、ユーザーが示した意見・予定から書く。元資料が抽象的でも、説得力を演出する数字、体験、発言、感情は作らない。確認が要る事実は未確定として扱う。

## 通読して選ぶ

候補を原文や資料と照らし合わせ、次を確認する。思考過程やチェックリストを出力する必要はない。

1. **伝える内容**：主体、対象、時点、否定、条件、確かさ、因果の向きが保たれ、新しい主張に根拠があるか。
2. **読み進めやすさ**：前の文を受けて読めるか。読み返す必要がある箇所を解消し、必要な説明を削っていないか。
3. **書き手の声**：よかった表現が残っているか。一般的な模範解答の語彙や調子に均していないか。
4. **変更の必要性**：元の表現より改善したと言えるか。単なる好みの置換なら戻し、必要な修正は残す。

修正理由が残った箇所だけをもう一度直す。新しい問題がなければ仕上げる。全文の再生成や自己採点を反復して「満点」に近づけない。機械検査が通っていても、意味や文体の判断は省略しない。

## 判断の小さな例

これらは編集方針の例であり、必須の言い換えではない。

- 「資料を確認することが可能です。」→「資料を確認できます。」：可能という意味と丁寧さを保って短くする。
- 「雨はやんだ。まだ、出かける気にはならない。」→そのまま：短さや間に役割があり、自然な文を整え直す理由がない。
- 「この結果は改善を示唆するが、効果を確認したわけではない。」→留保を残す：「改善を確認した」に縮めない。
- 「情報共有は重要である。」→資料がなければ具体的な成果を追加しない：「返信時間が短縮した」などを補うには根拠が要る。

## 出力の調整

本文を先に返す。文章を求められたらつながりのある段落で書き、項目の比較や手順に向くときだけ箇条書きや表を使う。求められていない見出し、冒頭の方針宣言、末尾の総括、複数案は付け足さない。修正理由や未確認事項は、必要なものだけ本文の外に短く示す。

この運用はAstraの公式ガイドが扱う書式・文体の明示と指示の整理を、このSkillの日本語執筆方針へ適用したものである。Astraで自然さが改善することを比較実験で証明したものではない。
