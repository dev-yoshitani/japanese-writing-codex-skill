# Optional verification core

通常の文章作成では従来のmode・genre方針を使う。数値、用語、文字数などの確認をコードで行う場合だけ、このreferenceを読む。

## 実行条件

Full版の `scripts/jw.py` と `src/jw/`、Python 3.10以降が必要である。Lite版には実行コードを含めない。
外部パッケージ、APIキー、ネットワーク接続は不要である。
パスはスキルのインストール先を基準に解決する。
元文章を一時ファイルへ保存するかどうかは、その作業環境とユーザーの指定に従う。標準入力 `-` も使用できる。

```text
python scripts/jw.py audit input.txt --genre report --max-chars 400 --json
python scripts/jw.py compare original.txt revised.txt --genre technical --glossary glossary/example.yaml --json
```

## 判定の扱い

- `FAIL`: 保護対象の変更・消失・追加、空の稿への置換、または明示された制約への違反がある。報告された対応文を確認し、保護対象を回復する。依頼に明示された事実訂正は別の作業として扱い、誤った原文を保持するために訂正を撤回しない。
- `WARN`: 文対応の不確かさやlintの指摘がある。指摘だけを根拠に文章を書き換えない。正しい専門用語、真正な三項列挙、必要な反復は保持する。
- `PASS`: 設定した機械検査では違反が見つからなかった。意味の正しさ、主張の出典、応募資格、技術的な妥当性は保証しない。

文字数は既定で改行・空白を含むUnicodeコードポイント数である。
提出先の数え方に合わせて `--count-mode no_newlines` または `no_whitespace` を指定する。
厳密な書式指定や結合文字・絵文字を含む場合、提出先の表示と一致するか別途確認する。

## 保護範囲

算用数字、単位付きの漢数字、対応する単位表記、算用数字の日付・時刻、URL、明示された数式、コード、辞書語を検査する。
URLは空白や山括弧で区切る。数式は `$...$`、`$$...$$`、`\(...\)`、`\[...\]` を使い、変数や記号単体は辞書語へ登録する。
未登録の固有名詞・専門語、裸の漢数字、未知の日本語単位、否定、確信度、因果、意味上の主張の追加は保証範囲に含めない。
数値が同じでも対応する対象や条件が変わる場合がある。文対応はヒューリスティックであり、結果を必要に応じて人が確認する。

## 修正ループ

ライブラリの `jw.pipeline.run` と `jw.adapters` は、呼び出し側が用意するモデル関数または明示的なreplay応答を利用する。
初回提案のあと、最大2回、findingに対応する原文の文IDだけを修正できる。全文の文字数など全体制約では対象IDが全体に及ぶ。
全文のマスク済み原文は読み取り用の文脈として渡す。これによって修正可能な文IDが増えることはない。警告だけが残り、モデルが変更不要として空の修正を返した場合は再試行せず終える。
モデル出力はJSON Schemaと実行時の文ID検査を通し、保護値のプレースホルダーを同じ文・同じ順序で復元する。
このループは `edit` 専用である。全文の再構成は別途行い、`compare` で検証する。
最終判定が `FAIL` の場合、ループの `output` は `None` となり、CLIは候補稿ファイルを生成しない。

既定のレポートに本文や保護値は含めない。値の表示が必要な場合のみ `--include-values` を明示する。
API通信やプロバイダーへのログ保存は呼び出し側の責任であり、検証器自体は通信・自動記録を行わない。
